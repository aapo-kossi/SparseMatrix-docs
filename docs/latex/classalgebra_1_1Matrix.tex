\doxysubsection{Detailed Description}
\subsubsection*{template$<$\mbox{\hyperlink{conceptMatrixTraits_1_1Numeric}{Matrix\+Traits\+::\+Numeric}} T, \mbox{\hyperlink{namespaceMatrixTraits_a797de13233dd3a54202f67d529912f32}{Matrix\+Traits\+::\+Storage\+Order}} O, std\+::integral I = index\+\_\+type$<$\+T$>$\+::type$>$\newline
class algebra\+::\+Matrix$<$ T, O, I $>$}
Represents a sparse mathematical matrix. 

This class provides functionality for storing and operating on sparse matrices of arithmetic or complex values. A sparse matrix can be stored in row-\/major or column major format, corresponding to the dimension with larger stride when iterating the matrix elements. In memory, a \doxylink{classalgebra_1_1Matrix}{Matrix} may be stored in compressed or uncompressed format. An uncompressed matrix may freely be modified by assigning, inserting or deleting elements at an arbitrary position. An ordered map is used with such an ordering that the map is efficiently iterated in row-\/major or column-\/major order.

A compressed matrix is stored as compressed sparse row (column) format for row-\/major (column-\/major) ordering. Use compressed formats for efficient calculations.

The choice of storage order depends on if access to sliced rows or columns is needed more often, since major axis slicing results in sequentially iterating the stored data, whereas slicing the minor axis always requires sparse memory accesses.

By default, a \doxylink{classalgebra_1_1Matrix}{Matrix} is indexed by an unsigned integer type matching the size of the stored elements, or in the case of complex valued elements, the size of the real and imaginary components.

The maximum number of rows and columns of the matrix is limited by the size of I, and the number of non-\/zero elements cannot exceed the maximum value of the size\+\_\+t type.
